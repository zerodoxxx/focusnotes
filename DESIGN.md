# Design

Last Updated: 2026-10-22 (previous commit: `3e925fa`)

## Product surfaces

focusnotes runs as a macOS accessory app and puts its always-available commands in a status-bar menu. The menu includes selection and area capture, note search, session control, quick-note writing, subheading entry, the notes folder, semantic-model controls, permission links, an optional updater item, and Quit. ([Sources/App/main.swift](Sources/App/main.swift#L6-L7), [Sources/App/AppController.swift](Sources/App/AppController.swift#L1020-L1069))

The default global shortcuts are ⌥⇧C for selection capture, ⌥⇧S for area capture, ⌥⇧F for search, ⌥⇧A for session control, ⌥⇧N for a quick note, ⌥⇧H for a subheading, and ⌥⇧L for the notes folder. Outside-session captures use ⌃⇧C for selected text and ⌃⇧S for an area. They open Add to note… immediately, with note suggestions; Escape saves to Inbox. Both work with or without an active session and leave it unchanged. The toast names the destination and, when present, the still-active session. Re-pressing a normal capture shortcut during its toast still opens the existing destination picker. ([Sources/CaptureKit/Hotkeys.swift](Sources/CaptureKit/Hotkeys.swift#L49-L55)) These are registered as exclusive Carbon hotkeys; if registration fails, the menu keeps the command, removes its shortcut indication, and exposes a retry command with a reason in the tooltip. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L218-L243), [Sources/CaptureKit/Hotkeys.swift](Sources/CaptureKit/Hotkeys.swift#L89-L121), [Sources/App/AppController.swift](Sources/App/AppController.swift#L1087-L1111))

The interactive surfaces are borderless, nonactivating panels: they borrow keyboard focus while leaving the app inactive, and they cannot become the main window. Passive toast panels ignore mouse events. ([Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L39-L64), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L66-L76)) Interactive panels without a saved movable position are centered on the pointer's screen, with their top edge 22% of the visible screen height below the top; toasts are placed 72 points above the visible bottom. ([Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L210-L223), [Sources/OverlayKit/Theme.swift](Sources/OverlayKit/Theme.swift#L137-L149))

### Sessions

In the duplicate-session picker, ⌘↩ on macOS or Ctrl+Enter on Windows opens a rename field with the highlighted session's title selected. Return renames its file and title heading, keeps it in the same folder, and resumes it. Escape returns to the picker with the same selection. Rename rejects folder separators and existing destination names, including case-insensitive matches. The rewrite preserves the remaining Markdown and relative image links, and pins, pending captures, session state, and search follow the new path. A unique match still resumes directly without a picker.

Changing only letter casing is rejected with “Choose a name that changes more than letter casing.” On Windows, other rename failures keep the entered name selected and show guidance for an occupied name, invalid name, missing session, or changed file; unexpected failures show “Check the name and file access. Existing files are kept.” If the file has moved but state migration needs another attempt, the app shows “Session rename pending · Daily sync” (using the new title) with “State updates will retry before the next save.” Recovery retries at startup and before further saves. Windows abandons stale uncommitted intents without modifying either note, and preserves edits to a known renamed file while completing migration. macOS abandons them the same way, so a stale rename never keeps the app from starting. ([windows/src/CaptureApp.AppCore/Shell/Strings.cs](windows/src/CaptureApp.AppCore/Shell/Strings.cs), [windows/src/CaptureApp.AppCore/Shell/CaptureCoordinator.cs](windows/src/CaptureApp.AppCore/Shell/CaptureCoordinator.cs), [windows/src/CaptureApp.AppCore/CapturePipeline.cs](windows/src/CaptureApp.AppCore/CapturePipeline.cs))

Starting a session with a bare name resumes its only matching note at the existing path, or creates a new top-level note under `Sessions/` when there is no match. Duplicate bare-name matches open a picker with each note's title, path, and modification date, newest first; Up/Down selects, Return resumes the selected path, and Escape cancels. A valid slash-qualified name such as `archive/Standup` resolves directly under `Sessions/` and skips the picker. Relative malformed slash forms, including whitespace next to a slash or trailing/repeated separators, use the cleaned flat-name matching flow; a leading slash after title cleaning is an explicit HOME-relative target for typed notes and remains invalid for sessions. ([Sources/Core/SessionStore.swift](Sources/Core/SessionStore.swift), [Sources/App/AppController.swift](Sources/App/AppController.swift), [Sources/OverlayKit/InputPanel.swift](Sources/OverlayKit/InputPanel.swift))

### Quick note

The quick note is a floating text editor with a centered title, a 38-point top band, a 38-point footer, and a 20-point text inset. Its five top-band buttons close the editor, invoke “Open as Note,” browse notes, start a new note, or show Actions; the footer shows the save shortcut, Actions shortcut, and Escape hint. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L366-L375), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L472-L474), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L481-L485), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L961-L969), [Sources/OverlayKit/NoteChrome.swift](Sources/OverlayKit/NoteChrome.swift#L84-L103), [Sources/OverlayKit/Theme.swift](Sources/OverlayKit/Theme.swift#L68-L74))

At rest, the top-band controls and footer are transparent and inactive, while the title is drawn at 30% opacity; pointer entry or a held reveal state shows the controls and footer and raises the title to 60% opacity. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L488-L495), [Sources/OverlayKit/NoteChrome.swift](Sources/OverlayKit/NoteChrome.swift#L104-L105), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L542-L560), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L565-L582), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L607-L611), [Sources/OverlayKit/Theme.swift](Sources/OverlayKit/Theme.swift#L86-L100)) The close and open buttons sit at the left edge; Browse, New Note, and Actions sit in a capsule at the right. ([Sources/OverlayKit/NoteChrome.swift](Sources/OverlayKit/NoteChrome.swift#L84-L103), [Sources/OverlayKit/NoteChrome.swift](Sources/OverlayKit/NoteChrome.swift#L120-L140))

The title is the destination name when one is selected, otherwise it comes from the first 2,000 characters of nonblank note text through the app's note-title rule, with “New note” as the empty fallback. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L519-L548), [Sources/App/AppController.swift](Sources/App/AppController.swift#L750-L782), [Sources/OverlayKit/Theme.swift](Sources/OverlayKit/Theme.swift#L92-L94)) The footer labels the save action “Add to note” when a destination is selected or the text names an existing note, and “Create note” otherwise. “Names an existing note” uses the same rule as saving (`CaptureService.appendTarget`): a bare Inbox name, or the one path the name resolves to when it exists on disk or was reserved by an unsaved save; there is no matching by title or across folders, and a generated timestamp title never matches. Save as New Note is available only when no Browse destination is selected and session routing is inactive (including Write outside session) and the typed name resolves to an existing or reserved note (reservations compare case-insensitively). A restored-draft label is shown only if the footer still fits. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L509-L548), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L550-L560), [Sources/App/AppController.swift](Sources/App/AppController.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift)) A failed pin identity lookup after a successful save produces a warning toast while preserving the saved note. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L505-L514), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L530-L540), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift))

When no session or Browse destination is active, the first nonblank line supplies the saved note name. Valid unprefixed slash-separated names identify folders under the vault; a leading `/` after title cleaning resolves from HOME. For relative names, a URL-shaped form, a trailing or repeated slash, or whitespace adjacent to a slash uses the legacy flat filename cleanup; malformed leading-slash HOME paths remain validation errors. Other explicit path validation errors remain visible instead of being converted to a generic filename error. The full path is resolved before display truncation; the quick-note title shows the final component with the existing 60-character cap, and a typed note whose resolved path already exists (or Inbox) is appended to; Save as New Note creates a numbered file in the same folder instead. Missing folders are created and existing folder/file casing is reused without regard to case. An active session directs typed notes to its `Sessions/` note by default. While a session is active, Write outside session (⇧⌘N, also in Actions) toggles this note to standalone routing: the first nonblank line names its destination, Browse may select an existing note, and pin-on-save and Save as New Note retain their usual behavior. The title shows the resolved note instead of the session. Toggling again, or ⌘N on a blank editor, restores the session destination. Saving or closing resets the transient choice while preserving the session; closing still keeps draft text. The next ordinary quick note or capture uses the session again, and an outside-session save toast names both the saved note and the still-active session. ([Sources/Core/TypedNote.swift](Sources/Core/TypedNote.swift), [Sources/Core/NoteTitle.swift](Sources/Core/NoteTitle.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift), [Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift))

HOME-relative notes enter search and Browse only through exact paths in the durable external-note registry; Focusnotes does not scan HOME. Capture preparation reuses one validated registry snapshot, and registry errors stop destination routing instead of allowing a capture to be routed against an incomplete note list. When the vault volume is unavailable, deterministic fallback routing is allowed only if that valid snapshot has no external registrations. The registry caches a validated path snapshot and generation, invalidated when its file or parent changes. FSEvents observes only the vault root. Registered external paths use at most 128 `O_EVTONLY` vnode descriptors total, including registry file/parent handles, and at most 64 registered-note parent-directory watches; uncovered paths are fingerprint-polled every 15 seconds by checking exact registered paths. External vnode setup, snapshot, and registry failures request a full sync for each newly reported failure key; repeats of the same key are logged once until recovery clears it, while a distinct key still requests its own sync. If the vault FSEvents stream cannot start, the watcher reports the failure and requests a full sync, then remains stopped until an explicit start retry succeeds. Uncovered external paths retry watcher setup after descriptors close and on a timer. A nonrecursive vnode can watch HOME as the nearest existing parent for re-arming missing paths. A malformed, unsupported, or unsafe registry is preserved and disables external notes with a warning until a valid registry is restored. Images in nested or external notes keep relative Markdown links back to the selected vault's `assets/` directory. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift), [Sources/Core/ExternalNoteRegistry.swift](Sources/Core/ExternalNoteRegistry.swift), [Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift), [Sources/Core/VaultWatcher.swift](Sources/Core/VaultWatcher.swift), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift#L88-L95), [Sources/Core/CaptureFormat.swift](Sources/Core/CaptureFormat.swift#L163-L189))

The editor renders Markdown while editing: headings, unordered and ordered lists, task lists, block quotes, bold, italic, strikethrough, inline code, links, and fenced code receive distinct typography or decoration. ([Sources/OverlayKit/MarkdownStyler.swift](Sources/OverlayKit/MarkdownStyler.swift#L149-L175), [Sources/OverlayKit/MarkdownStyler.swift](Sources/OverlayKit/MarkdownStyler.swift#L177-L224), [Sources/OverlayKit/MarkdownStyler.swift](Sources/OverlayKit/MarkdownStyler.swift#L226-L263)) Markdown markers are hidden outside the active editing or composition range, and become visible when the selection enters the corresponding element. ([Sources/OverlayKit/MarkdownLayoutManager.swift](Sources/OverlayKit/MarkdownLayoutManager.swift#L27-L49), [Sources/OverlayKit/MarkdownLayoutManager.swift](Sources/OverlayKit/MarkdownLayoutManager.swift#L198-L225), [Sources/OverlayKit/MarkdownLayoutManager.swift](Sources/OverlayKit/MarkdownLayoutManager.swift#L261-L276)) Clicking a rendered task checkbox toggles its stored marker; Return continues list markers, numbers ordered lists, and Tab/Shift-Tab indents or outdents list lines. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L160-L193), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L294-L340))

The editor saves with ⌘Return, toggles Actions with ⌘K, and maps ⌘P to Browse, ⌘N to New Note, ⇧⌘N to Write outside session while a session is active, ⌘O to Open as Note, ⇧⌘P to pin, ⇧⌘C to copy Markdown, ⇧⌘Delete to discard the draft, and ⌥⌘Return to Save as New Note (a plain save when the text names no existing note). ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L202-L224), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L645-L648), [Sources/OverlayKit/NoteChrome.swift](Sources/OverlayKit/NoteChrome.swift#L95-L103), [Sources/OverlayKit/NoteChrome.swift](Sources/OverlayKit/NoteChrome.swift#L144-L157)) Escape closes an open card or the editor; ⌘K closes Actions or switches from Browse to Actions. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L634-L642), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L731-L752), [Sources/OverlayKit/NoteActionMenu.swift](Sources/OverlayKit/NoteActionMenu.swift#L210-L218))

The note begins at 400 points wide and can grow to 600 points based on content or footer width; its text viewport has a two-line minimum and a cap derived from the lower of 60% of the visible screen height or 680 points, less the top and bottom bands. ([Sources/OverlayKit/Theme.swift](Sources/OverlayKit/Theme.swift#L68-L70), [Sources/OverlayKit/Theme.swift](Sources/OverlayKit/Theme.swift#L97-L101), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L926-L949)) Longer text scrolls, and width only grows while the panel remains open. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L926-L945)) The editor can be dragged from its top or bottom band and remembers its position as fractions of the visible screen; it remains open when it resigns key or the active Space changes, while other interactive panels dismiss when they resign key. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L583-L589), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L1048-L1050), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L10-L16), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L39-L64), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L157-L181), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L226-L234), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L251-L267))

### Actions and Browse cards

Actions and Browse appear as one card below the quick note's top band. ([Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L409-L423), [Sources/OverlayKit/NoteEditorPanel.swift](Sources/OverlayKit/NoteEditorPanel.swift#L630-L657), [Sources/OverlayKit/OverlayPanel.swift](Sources/OverlayKit/OverlayPanel.swift#L306-L315)) Both cards have a filter field and a separator above their content. ### Toast feedback

## Windows edition

The implemented Windows edition keeps the Mac product surfaces above and changes only what the platform forces or what a new first-launch flow needs. Windows installers are not part of the currently published releases. Its user-visible strings come from one table, with the Mac's wording and these maps: Ctrl for ⌘, "File Explorer" for "Finder", "tray icon" for "menu bar icon", Setup for Permissions, and the user's current shortcut in place of the Mac's ⌥⇧ hints. ([windows/src/CaptureApp.AppCore/Shell/Strings.cs](windows/src/CaptureApp.AppCore/Shell/Strings.cs), [windows/src/CaptureApp.Platform/PlatformStrings.cs](windows/src/CaptureApp.Platform/PlatformStrings.cs))

### Tray menu

The app lives in the notification area with no taskbar button or main window; the icon has light, dark and attention variants. The menu keeps the Mac's order, with items in this sequence and each command showing the user's current shortcut: ([windows/src/CaptureApp.AppCore/Shell/TrayMenuBuilder.cs](windows/src/CaptureApp.AppCore/Shell/TrayMenuBuilder.cs), [windows/src/CaptureApp.Platform/Assets](windows/src/CaptureApp.Platform/Assets))

1. **Finish Setup… (n left)**, followed by a separator, only while a required Setup step is incomplete or a step has failed. Before the first Setup page is answered the menu contains only this item and **Quit**.
2. **Capture Selection**, **Capture Area**, **Search Notes…**, **Start Session…** (becoming **End Session “name”** during a session), **Write a Note…**, **Add Subheading…**.
3. When shortcuts failed to register: a disabled “N keyboard shortcuts unavailable” line and **Retry Shortcuts**.
4. A separator, then **Open Notes Folder**.
5. **Semantic Search**: **Enable Semantic Search…** (or **Resume Semantic Search…** after a partial download), **Downloading Models… n%**, **Removing Models…**, or a checked **Semantic Search** with **Remove Models…** beneath it.
6. **Setup…** and **Settings…**.
7. The update item, when updates are enabled: **Check for Updates…**, **Checking for Updates…**, **Downloading Update (vX)…**, **Restart to Update (vX)**, or **Update failed** with **Retry** and **Download installer**.
8. A separator, then **Quit <app name>**.

The attention badge appears while any required Setup step is incomplete or any step has failed; a skipped recommended step shows as “Not tested” and never raises it. Windows 11 may place a new icon in the overflow flyout, which Setup explains.

### Panels and focus model

Windows delivers keystrokes only to the focused window of the foreground thread, so a typing panel cannot borrow focus the way the Mac's nonactivating panels do (deviation DV1). The end state matches the Mac instead:

- Interactive panels (quick note, search, input, session picker) activate when they need typing. Clicks on a panel's buttons do not activate it and still run on the first click, as on the Mac. ([windows/src/CaptureApp.Overlay/OverlayWindow.cs](windows/src/CaptureApp.Overlay/OverlayWindow.cs))
- The panel remembers the last non-app foreground window from just before it activated, and refreshes that each time it is re-activated. An explicit close (save, Esc, ✕) returns focus to that window only if it still exists, is not minimized and is on the current virtual desktop; otherwise the app does nothing. Opening another focusnotes panel hands the remembered window to it, and quitting never restores focus. ([windows/src/CaptureApp.Overlay/OverlayWindow.cs](windows/src/CaptureApp.Overlay/OverlayWindow.cs), [windows/src/CaptureApp.App/ForegroundTracker.cs](windows/src/CaptureApp.App/ForegroundTracker.cs))
- Clicking another window leaves focus there and the app makes no foreground call afterwards. The quick note stays visible (sticky); search and input dismiss, including on a virtual-desktop switch.
- Pressing the Write shortcut on a visible but inactive quick note re-activates it with text, caret and scroll kept; on the active note it closes and keeps the draft.
- Toasts are click-through, never activate, stay out of the taskbar and Alt+Tab, and sit topmost 72 DIPs above the work area's bottom edge; geometry, sizes and timings use the Mac's values in DIPs against the monitor's work area, with per-monitor DPI awareness. Panel positions are saved as screen fractions in `settings.json`.

Keyboard keys inside the quick note use Ctrl for ⌘: Ctrl+Enter saves, Ctrl+K opens Actions, Ctrl+P browses, Ctrl+N starts a new note, Ctrl+Shift+N toggles Write outside session while a session is active, Ctrl+O opens as note, Ctrl+Shift+P pins, Ctrl+Shift+C copies Markdown, Ctrl+Shift+Backspace discards the draft, Shift+Enter inserts a plain newline, and Ctrl+Z with Ctrl+Y or Ctrl+Shift+Z undo and redo. In search, Enter copies, Ctrl+Enter opens, and Alt+Enter shows the note in File Explorer. ([windows/src/CaptureApp.Platform/Hotkeys/KeyChord.cs](windows/src/CaptureApp.Platform/Hotkeys/KeyChord.cs))

### Toasts

Toast styles, strings and durations follow the Mac. Windows adds these: “Can't capture from apps running as administrator” with “Use Capture Area (<shortcut>) instead”; “Release the shortcut keys and try again” when modifier keys are still held; “Couldn't capture selection” with “Your clipboard is too large to restore safely” when the clipboard fallback cannot restore safely; “Can't capture from secure fields”; “No text selected” with “This app doesn't share its selection; turn on the clipboard fallback in Settings” when the fallback is off; “Finish Setup to capture” before the first Setup page is answered; and “Setup needs attention” with “Open the tray icon → Setup” when a launch-time check regresses. ### Setup

Setup opens on the first launch, again at the first incomplete required step on later launches, and from tray → **Setup…**. It is a window with a step list on the left, each step showing Passed, Needs attention, Skipped, “Not done yet” (required) or “Not tested” (recommended). ([windows/src/CaptureApp.App/SetupWindow.cs](windows/src/CaptureApp.App/SetupWindow.cs), [windows/src/CaptureApp.AppCore/Shell/SetupModel.cs](windows/src/CaptureApp.AppCore/Shell/SetupModel.cs))

| Step | Class | What it does |
| --- | --- | --- |
| 0 Disclosure and consent | Required | Lists what the app uses and when: system-wide shortcuts, reading the selection through UI Automation, the clipboard fallback, screen pixels during Capture Area, files in the notes folder and state directory, and network use. Asks two explicit questions: use the clipboard fallback or not, and check for updates automatically (daily) or only on request. No shortcut is registered and no capture runs until both are answered. |
| 1 Notes folder | Required | Shows the default or another folder and runs a write probe; failures explain the cause and offer another folder. Captures still journal meanwhile. |
| 2 Keyboard shortcuts | Required | Registers all nine, shows each result, runs the AltGr guard, and lets each shortcut be changed, turned off or retried. |
| 3 Selection capture test | Recommended | Asks the user to select a sample sentence and press the Capture Selection shortcut. |
| 4 Area capture test | Recommended | Captures a region and confirms the image is written and OCR finds text. |
| 5 Tray icon | Recommended | Confirms the icon is visible and explains the overflow flyout. |
| 6 Start at login | Recommended | A pre-checked toggle stored as a per-user Run entry; also manageable in Windows Settings → Apps → Startup. |
| 7 Updates | Recommended | Shows the choice made in step 0 for review. |
| 8 Semantic search | Recommended | A pointer to the opt-in; nothing is downloaded here. |

Progress is saved after every step, so closing the window or killing the app resumes where it stopped. Every launch silently re-checks the cheap conditions (notes folder writable, shortcuts registered, Run entry present, update choice present) and flips a regressed step to failed. A release that adds steps shows only the new ones.

### Settings

Settings has three tabs. **Shortcuts** lists the nine actions with **Change…** (press the new combination), **Turn off** or **Turn on**, **Check again** and **Reset to defaults**. **General** holds **Start at login**, **Use the clipboard fallback for Capture Selection** (with a note that the target app's own copy may appear in clipboard history), and the **Notes folder** chooser, which applies after a restart. **Updates** holds the automatic or on-request choice and **Check now**. ([windows/src/CaptureApp.App/SettingsWindow.cs](windows/src/CaptureApp.App/SettingsWindow.cs), [windows/src/CaptureApp.App/ShortcutsPanel.cs](windows/src/CaptureApp.App/ShortcutsPanel.cs))

### Shortcuts, rebinding and the AltGr guard

The defaults are Alt+Shift plus Q (Capture Selection), G (Capture Area), F (Search), A (session), W (Write a Note), H (subheading) and E (notes folder), matching the Mac's Option+Shift modifier pair. Ctrl+Shift+Q and Ctrl+Shift+G capture selected text or an area outside the session and open the note picker immediately; Escape saves to Inbox. Both are rebindable in Settings. Saved custom bindings are preserved; Reset to defaults applies the current defaults. A rebinding is rejected if it uses the Windows key, uses Ctrl+Alt without Shift (Windows treats it as AltGr), duplicates a key used inside the note panels, or cannot be registered; it is test-registered before it is saved. Custom Ctrl+Alt+Shift+letter bindings equal AltGr+Shift+letter on some keyboard layouts, so the guard checks each installed layout, refuses a combination that types a character, and proposes a free letter with the default Alt+Shift modifiers. A registration failure shows the “Some keyboard shortcuts are unavailable” toast, the tray status line and a Retry command. ([windows/src/CaptureApp.Platform/Hotkeys/KeyChord.cs](windows/src/CaptureApp.Platform/Hotkeys/KeyChord.cs), [windows/src/CaptureApp.Platform/Hotkeys/AltGrGuard.cs](windows/src/CaptureApp.Platform/Hotkeys/AltGrGuard.cs), [windows/src/CaptureApp.Platform/Hotkeys/HotkeyBindingStore.cs](windows/src/CaptureApp.Platform/Hotkeys/HotkeyBindingStore.cs))

### Deviations from the Mac

Each difference below is intentional, has a cited platform cause, and is checked by an outcome test.

| ID | Difference | Effect |
| --- | --- | --- |
| DV1 | Interactive panels activate for typing instead of borrowing focus; button clicks do not activate. | Same end state; while typing, the other app shows as inactive and may close an open dropdown. |
| DV2 | Selection capture cannot read apps running as administrator (Windows blocks it for a normal-integrity app). | A toast points to Capture Area, which still works. |
| DV3 | Different default shortcuts, plus rebinding. | Same capture and note actions. |
| DV4 | The English-first Windows POC uses RapidOcrNet's bundled PP-OCRv5 Latin set through ONNX Runtime. | Multilingual language selection is deferred; recognised text can differ slightly from the Mac. |
| DV5 | No thermal signal exists. | Background embedding runs at low priority with EcoQoS instead of waiting on temperature. |
| DV6 | A stricter clipboard fallback: it aborts if the clipboard is too large or unreadable, or while keys are held. | A refusal toast where the Mac would capture. |
| DV7 | Windows file-name rules reject names the Mac accepts (`CON`, `a:b`, a trailing dot). | The same reserved-name message. |
| DV8 | The target app's own copy may appear in Windows clipboard history during the fallback. | One extra history entry; disclosed in Setup. |
| DV9 | Ctrl for ⌘, File Explorer for Finder, tray for menu bar. | Wording and keys only. |
| DV10 | ONNX Runtime ships in the installer, so the semantic opt-in downloads only models. | Larger installer, smaller opt-in. |
| DV11 | Additions with no Mac counterpart: Setup, Settings, start at login, single instance, log files, update-key rotation. | New windows and settings. |
