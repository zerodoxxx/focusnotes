## Runtime and package boundaries

This document describes both native FocusNotes editions. The package boundaries below cover macOS; the implemented
Windows edition under `windows/` is covered in [Windows edition](#windows-edition). Current GitHub releases include
Windows installers for x64 and arm64.

## App startup and ownership

On normal launch, `ApplicationDelegate` reads `vaultPath` from `UserDefaults` or selects `Documents/<app name>`, and places app state under `Library/Application Support/<bundle identifier>`. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L21-L33), [Sources/App/AppInfo.swift](Sources/App/AppInfo.swift#L3-L14))

`CapturePipeline.open` prepares the vault and constructs the session store, note writer and capture service, keyword index, semantic indexer, vault monitor, capture journal, draft store, and pin store. The keyword database is `index.sqlite`; the semantic indexer owns a separate `vectors.sqlite` database, and the models directory defaults to `<state>/models` unless an override is passed. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L46-L72), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L35-L50))

`AppController` is main-actor isolated and coordinates UI commands, while `CapturePipeline` exposes the storage and indexing services used by those commands. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L115-L126), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L33-L44))

Startup replays unsaved journal records before loading the current session; for interactive launches it then registers shortcuts, installs the menu bar item, and may show the Accessibility guide, before starting vault observation, index synchronization, and OCR backfill. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L183-L215))

Termination stops the watcher and semantic work, unregisters hotkeys, and drains acquisition and save work for five seconds by default. Quick notes, subheadings, session names and session choices the user already submitted but still queued behind a busy action run within that drain; new commands are refused once quit begins, and nothing queued starts after the deadline. It waits for recovery-journal writes and logs failures, while timeout logs that prepared captures remain in the journal. Actual retention depends on those journal writes succeeding. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L447-L515), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L27-L35))

## Capture and save path

Carbon global hotkeys invoke selection capture, area capture, search, session toggle, note editor, subheading entry, and vault-folder opening; registration failures are retained and surfaced while menu commands remain available. ([Sources/CaptureKit/Hotkeys.swift](Sources/CaptureKit/Hotkeys.swift#L49-L63), [Sources/CaptureKit/Hotkeys.swift](Sources/CaptureKit/Hotkeys.swift#L89-L121), [Sources/App/AppController.swift](Sources/App/AppController.swift#L218-L244), [Sources/App/AppController.swift](Sources/App/AppController.swift#L1020-L1069))

Capture context is snapshotted at hotkey entry. For Safari, Chrome, and Edge, it also attempts a bounded macOS Accessibility scan of the browser toolbar and retains a complete HTTP(S) address-bar URL when available. It skips a focused address field, which may contain an unsubmitted edit, and never inspects page contents or selected text to find a URL. An unsupported, incomplete, or inaccessible field yields no URL and does not block capture. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L260-L274), [Sources/CaptureKit/FrontmostContext.swift](Sources/CaptureKit/FrontmostContext.swift#L17-L41), [Sources/CaptureKit/BrowserAddressURL.swift](Sources/CaptureKit/BrowserAddressURL.swift), [Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L71-L84), [Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L87-L129)) Selection capture first reads the focused element's Accessibility selection, then may use a Command-C clipboard fallback that snapshots and conditionally restores pasteboard contents.

The selection path checks secure-input state, Accessibility trust, and whether the captured app remains frontmost; area capture checks Screen Recording permission and invokes `/usr/sbin/screencapture` to write a PNG in a temporary directory. ([Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L72-L80), [Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L97-L129), [Sources/CaptureKit/RegionCapturer.swift](Sources/CaptureKit/RegionCapturer.swift#L25-L34), [Sources/CaptureKit/RegionCapturer.swift](Sources/CaptureKit/RegionCapturer.swift#L43-L75))

Vision OCR classifies a region as text or image from OCR coverage, confidence, and line count; if OCR takes more than 1.5 seconds, the pending capture retains the PNG and holds OCR for deferred completion. ([Sources/CaptureKit/CaptureClassifier.swift](Sources/CaptureKit/CaptureClassifier.swift#L19-L48), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L226-L258))

`Capture` represents text, image, subheading, and typed-note content with a UUID, timestamp, and `CaptureSource`; that source carries optional app/window metadata and URL. Ordinary captures with a non-empty note title match root-note titles first, session titles second, then Inbox; an unmatched title creates a new root note. Without a note title, routing selects the active session or Inbox. Outside-session capture shortcuts open the title picker immediately and explicitly route Escape to Inbox. Their chosen title uses ordinary capture routing without changing the session. Standalone typed notes retain an explicit Browse destination or append to the active session, unless the editor has selected Write outside session for this note. That transient choice bypasses session routing while preserving session state; it resets on editor close or save, like a Browse destination. When a typed note has neither a Browse destination nor session routing, `TypedNote` extracts the first-line name: valid unprefixed slash-separated names resolve beneath the vault, and a leading slash after title cleaning resolves beneath HOME. Relative malformed slash forms such as URLs, trailing or repeated separators, and whitespace adjacent to a separator use the legacy flat filename cleanup; explicit HOME, traversal, length, depth, reserved `assets/`, and `~$` leaf errors remain errors. Existing folder and filename casing is reused case-insensitively. A typed note's name resolves to exactly one path (`archive/foo` is `archive/foo.md`, `foo` is the vault-root `foo.md`); there is no matching by title or across folders. `CaptureService.appendTarget` is the shared, non-mutating rule that both `prepareNote` and the quick-note “Add to note”/Save as New Note hint use: a bare name matching Inbox appends to `Inbox.md`; otherwise a resolved path that exists on disk, or was reserved by an earlier unsaved typed note in the same process (compared case-insensitively), is appended to. Otherwise the path is created. A title-only note appends its own text. A forced new note (Save as New Note) or a generated timestamp title always creates a note, taking a numbered ` 2`, ` 3`, … suffix in the same folder when the path exists or is reserved. New parent folders are created during the managed write. Starting a session is unchanged: it resumes a flat session note by exact file name or legacy dated file name, and qualified session names are rooted under `Sessions/`. ([Sources/Core/Capture.swift](Sources/Core/Capture.swift), [Sources/Core/Router.swift](Sources/Core/Router.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift), [Sources/Core/TypedNote.swift](Sources/Core/TypedNote.swift), [Sources/Core/NoteTitle.swift](Sources/Core/NoteTitle.swift), [Sources/Core/SessionStore.swift](Sources/Core/SessionStore.swift), [Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift), [Sources/App/AppController.swift](Sources/App/AppController.swift))

The pipeline prepares a fixed destination before saving, stores a job in the recovery journal before waiting on earlier commits, then writes via `CaptureService` and `NoteWriter`; image jobs carry a stable vault-relative asset path. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L75-L94), [Sources/App/AppController.swift](Sources/App/AppController.swift#L393-L423))

Journal records are JSON plus an optional PNG under the app state's `unsaved/` folder; replay preserves the prepared destination, uses an available OCR transcript if a journaled PNG is missing, and quarantines records that fail record decoding or identity validation. ([Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L13-L35), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L41-L92), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L141-L163))

Text and image capture markers include an identity and timestamp. When the capture source contains a valid URL, the Markdown block adds a separate `[Source](<...>)` link after the marker and before its content; the URL is not duplicated in the hidden marker or heading. Typed-note markers include an identity and timestamp, and subheading markers include an identity without a timestamp. Image jobs use a vault-relative `assets/` path that Markdown renders as a link; `NoteWriter` computes a relative prefix from the note's directory back to the selected vault, so nested and external notes still link to that vault's assets. `NoteParser` accepts indexed image links only when their resolved target is inside the vault's `assets/`. On retry, `appendIfMissing` passes a stable marker and `NoteFile` checks existing block content or the typed-note marker before suppressing a second append. ([Sources/Core/CaptureFormat.swift](Sources/Core/CaptureFormat.swift#L21-L41), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift#L53-L78), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift#L81-L95), [Sources/Core/CaptureFormat.swift](Sources/Core/CaptureFormat.swift#L163-L189), [Sources/Core/Index/NoteParser.swift](Sources/Core/Index/NoteParser.swift#L227-L270), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L400-L416), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L562-L570))

A failed per-capture reindex is logged without retrying the Markdown append; startup starts the watcher and runs `index.sync()` over vault notes, while sync failures are logged separately. Starting, resuming or ending a session reindexes or counts captures only after the session change is saved; an index error there is logged and the change still reports success (the end toast then omits the capture count). The journal record is removed after note-save and draft/pin completion. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L96-L123), [Sources/App/AppController.swift](Sources/App/AppController.swift#L205-L211), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L168-L176), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L63-L108))

On macOS, capture heading matches consider only notes directly under the vault root before considering session headings; nested and registered HOME notes require an explicit path. Multiple matches in the winning tier open a chooser with exact paths, and selecting a row saves to that destination without resolving its title again. Capture heading comparisons ignore case, accents, and character width. Typed-note paths and session filenames deliberately use case-insensitive filesystem matching instead; changing a session's heading does not change its filename-based resume name. All three entry points share legacy flat-name parsing for relative slash forms such as `pros / cons`, `TODO/`, and `a//b`, while explicit path safety validation stays strict. ([Sources/Core/Router.swift](Sources/Core/Router.swift), [Sources/Core/NoteTitle.swift](Sources/Core/NoteTitle.swift), [Sources/Core/TypedNote.swift](Sources/Core/TypedNote.swift), [Sources/Core/SessionStore.swift](Sources/Core/SessionStore.swift), [Sources/App/AppController.swift](Sources/App/AppController.swift))

On macOS, session changes drain an in-flight capture acquisition before processing and committing captures, so a clipboard fallback started in a session finishes routing before that session ends. A failed chosen-destination preparation keeps the capture pending and its recovery job intact; the warning offers the same capture shortcut to choose again, and neither warning expiry nor any implicit commit (another toast, `drainCaptures`, a rename, a draft or subheading save) saves it to the default destination; only an explicit destination or shutdown does, with one exception: a newer capture staged by `stage()` first commits it (below). Cancelling an ambiguity chooser also retains that choice for retry. If a newer capture is already pending when an earlier choice fails, that newer capture keeps its pending state, the earlier staged job remains queued for recovery, and the warning names its recovery destination; a newer capture arriving while one is retry-pending first commits the earlier one to its staged default destination (ordered before the newer one) and folds a "Previous capture saved to …" notice into the newer capture's toast, awaiting that commit first so a failure is reported (and the earlier job stays journaled for recovery) before the newer capture is staged. The capture shortcut reopens the chooser only while the retry warning is visible. A retry-pending capture otherwise survives until retried; after a crash or kill its journal record is replayed into the default destination on next launch. Failed appends truncate the attempted bytes back to the original note length before reporting the write error, preventing a partial typed-note marker from suppressing a later retry; if that truncation itself fails, the original write error is still reported. A crash, kill or power loss in the middle of an append, or a failed rollback (logged with its errno), can still leave a marker without its body, and replay then treats that block as saved. Successfully saved typed-note markers still identify a note after external body edits. If the note is replaced or unlinked while an append waits for its lock (an editor's atomic save, a session rename), the append retries against the file now at that path instead of failing the single-link check; after such a replacement it never recreates a missing path, so a note moved away fails the append and its journal record is kept. Ownership, file-type and hard-link problems on the current file still fail with EPERM. ([Sources/App/AppController.swift](Sources/App/AppController.swift), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift))

## Vault files and app state

The vault contains `Inbox.md`, Markdown notes at any depth, the `Sessions/` namespace, and the reserved `assets/` directory. `Vault.prepare` creates the managed directories and Inbox when they are missing; note discovery recurses through visible folders and excludes the root entry named `assets` case-insensitively, keeping case-variant asset folders out of the note index as well. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift#L187-L208), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L220-L228), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L231-L256), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L624-L664))

Standalone typed-note paths can target the vault or HOME. `external-notes.json` in app state records exact HOME-relative note paths before append so journal replay can reuse them; it stores no note contents and does not cause a HOME scan. The registry caches a validated path snapshot and generation, invalidated when its file or parent changes. Vault note IDs are vault-relative paths, while external note IDs are canonical file URLs. Listing and indexing include only registered external paths. Capture preparation validates and reuses one registry snapshot before scanning notes; registry errors remain visible instead of routing against an incomplete list. If the vault volume is unavailable, deterministic fallback routing is allowed only when the valid registry has no external registrations. A malformed, unsupported, or unsafe registry is preserved; external paths fail closed, a warning explains the condition, and registry-dependent listing, indexing, and capture routing pause until recovery. Local Markdown remains intact, and managed vault-file operations remain available. A valid registry recovery rebuilds external indexing and watching. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift), [Sources/Core/ExternalNoteRegistry.swift](Sources/Core/ExternalNoteRegistry.swift), [Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift))

Markdown notes and image assets are the persistent content; SQLite indexes and app-state JSON are separate derived or workflow state. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L45-L46), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L46-L72), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L21-L35), [Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L35-L43), [Sources/App/NotePinStore.swift](Sources/App/NotePinStore.swift#L3-L8))

An active session points to a note path under `Sessions/`, while its current name, path, and start date are persisted as `session.json` in app state; pinned-note paths are stored in `pinned-notes.json`, separately from Markdown. A bare name resumes one matching session at its full path, opens a newest-first title/path/date picker for duplicate matches, or creates a top-level session when there is no match. The picker also offers rename-and-resume with Cmd+Enter on macOS and Ctrl+Enter on Windows. Rename uses a same-directory temporary file and atomic replacement for the title heading, preserves managed-file identity and path checks, and exclusively publishes the new filename without overwriting a destination. The app migrates pins and pending capture destinations to the new ID and synchronizes the search index. A valid slash-qualified name resolves directly under `Sessions/`; relative malformed slash forms such as `pros / cons`, `TODO/`, or `a//b` fall back to the cleaned flat-name matching flow. A leading slash after title cleaning is an explicit HOME-relative target for typed notes and remains invalid for sessions; names containing NUL also remain errors. ([Sources/Core/SessionStore.swift](Sources/Core/SessionStore.swift), [Sources/App/AppController.swift](Sources/App/AppController.swift), [Sources/OverlayKit/InputPanel.swift](Sources/OverlayKit/InputPanel.swift), [Sources/App/NotePinStore.swift](Sources/App/NotePinStore.swift#L3-L8))

On Windows, `session-rename.json` durably records the source and staged-file identities, target, content hashes, and affected capture UUIDs before a rename changes the file. If the file moves but session or pin migration fails, the pipeline returns a pending outcome, keeps the intent, and retries recovery at startup and before further saves. Session start (including folder shortcuts), resume, and end recover pending renames under the same pipeline lock as captures and renames before changing session state. Recovery failures leave the requested session change unapplied; successful recovery cannot later override that choice. A known moved or installed inode is adopted even after user edits; only an untouched original heading is rewritten. If the source remains at its old path, or the target is missing or unrelated, recovery logs and abandons the stale intent while preserving note bytes, so it cannot repeatedly block startup or captures. An undecodable or incomplete intent moves to `unsaved/corrupt/` like a corrupt journal record. Cleanup deletes only staging files with the recorded identity. Search updates are best effort because the index is a cache. ([windows/src/CaptureApp.AppCore/CapturePipeline.cs](windows/src/CaptureApp.AppCore/CapturePipeline.cs), [windows/src/CaptureApp.AppCore/Shell/CaptureCoordinator.cs](windows/src/CaptureApp.AppCore/Shell/CaptureCoordinator.cs), [windows/src/CaptureApp.Core/SessionStore.cs](windows/src/CaptureApp.Core/SessionStore.cs), [windows/src/CaptureApp.Core/NoteFile.Rename.cs](windows/src/CaptureApp.Core/NoteFile.Rename.cs))

On macOS, the app-state `session-rename.json` records the same identities and capture UUIDs, plus each staging stage. Startup resumes an interrupted rename when the old path still holds the original or the app's staged file; if that file step fails, or the source was edited, replaced, or removed, recovery logs and abandons the intent without touching either note. Captures abandon a stale uncommitted intent too, but wait for startup to finish a staged swap. A move that installed before state persistence failed returns a pending outcome and finishes at the next recovery. Abandonment keeps any staging file that may hold the original or user edits, and a corrupt intent is quarantined like a corrupt journal record. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift))

The note editor draft and pin-on-save intent are stored together in `draft-note.json` using atomic replacement, with a legacy `draft-note.md` read path; note pins are separately serialized as an atomic JSON list. If a saved note's identity cannot be resolved for pinning, the note save succeeds and a warning makes the pin failure visible. ([Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L4-L7), [Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L35-L43), [Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L206-L239), [Sources/App/NotePinStore.swift](Sources/App/NotePinStore.swift#L34-L43), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift))

Vault and external HOME reads and writes use their selected root's retained directory descriptor and `openat` with `O_NOFOLLOW`; managed regular files must be owned by the current user and have one hard link. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift#L194-L208), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L390-L405), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L124-L176), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L207-L225))

## Keyword index and change monitoring

`SearchIndex` is a disposable SQLite cache: it checks FTS5 availability, validates an existing schema/version and SQLite integrity, and discards an invalid cache before creating a fresh one. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L45-L61), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L419-L449))

Its schema stores note metadata, parsed blocks, and image OCR text, then indexes note title, block body, and OCR text in an FTS5 table; the indexing code maps each parsed block and its OCR text into those fields. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L309-L343), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L451-L469))

`NoteParser` reads the Markdown title and recognized capture markers, and also retains ordinary Markdown regions as loose blocks for indexing. ([Sources/Core/Index/NoteParser.swift](Sources/Core/Index/NoteParser.swift#L22-L69), [Sources/Core/Index/NoteParser.swift](Sources/Core/Index/NoteParser.swift#L245-L268))

Index synchronization recursively scans visible Markdown below the vault root, excluding the root `assets` entry case-insensitively, and adds only exact external paths from the registry. It validates each file through its vault or HOME descriptor anchor, compares modification-time/size fingerprints, reparses changed files, and deletes cached rows for notes no longer present. A note that keeps changing while it is listed or read (EAGAIN, including an inode replaced mid-read) is retried twice, then skipped: its existing row is kept, `SyncStats.skipped` counts it, and the rest of the sync, including deletions, continues. The watcher's event for that write triggers the next sync, which picks it up. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift#L231-L256), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L524-L533), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L624-L664), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L63-L108))

Keyword search sanitizes query tokens before passing them to FTS5 and returns ranked hits with snippets; an empty search uses the recent-capture query. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L174-L216), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L381-L399))

`VaultWatcher` keeps recursive FSEvents on the vault root. Registered HOME notes use bounded `O_EVTONLY` vnode sources: at most 128 descriptors are retained in total, including registry file/parent sources, with no more than 64 registered-note parent-directory watches. A nonrecursive vnode may watch HOME when it is the nearest existing parent needed to re-arm a missing path. Paths without vnode coverage are fingerprint-polled every 15 seconds by checking exact registered paths only; HOME is never scanned. External vnode setup, snapshot, and registry failures request a full sync for each newly reported failure key; repeats of the same key are logged once until recovery clears it, while a distinct key still requests its own sync. If the vault FSEvents stream cannot start, the watcher reports the failure and requests a full sync, then remains stopped until an explicit start retry succeeds. Uncovered external paths retry watcher setup after descriptors close and on a timer, while healthy polling does not trigger periodic syncs. Parent events recheck only registered paths in that directory, suppress unrelated HOME churn, and rearm sources after file or parent replacement. The registry file and its parent are watched as control state; malformed, unsupported, or unreadable states clear external watches and request a full sync, and a valid recovery rebuilds them. Vault changes to nested Markdown and the top-level `assets` directory are reported in their respective note or asset paths, while FSEvents loss/root-change flags and relevant directory renames or removals request a full sync. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/VaultWatcher.swift](Sources/Core/VaultWatcher.swift), [Sources/App/VaultMonitor.swift](Sources/App/VaultMonitor.swift))

`VaultMonitor` coalesces changes into utility-priority index/OCR work without idle polling, and capture-pipeline backfill runs Vision OCR for image assets missing cached text. ### Conformance suite

### File layer, paths and naming

`NoteFile` replaces the Darwin `flock`/`open` layer: files are opened with exclusive sharing, appends are flushed to disk, atomic writes go through a temporary file and `File.Replace` (if it fails after removing the target, the temporary is moved into place; failing that, it is kept as a hidden `.recovered-` sibling that the stale-temporary sweep never deletes. Whether the target was lost is decided by file identity, not by whether its name is still visible (a delete-pending file still is), so the temporary is deleted only while the replaced file is still in place. If the lock that failed the replace also blocks renaming the temporary, it is copied to the kept name instead. Session rename cleanup keeps its staged copy under the restorable name when neither the old nor the new session name exists, and a pending rename whose session folder was deleted is abandoned rather than blocking startup. Only when the target was actually lost is the name `.recovered-<id>-<hex target name>` (restorable); other kept copies use the plain `.recovered-<id>` and are never restored. A restorable copy is moved back to the missing target name, never over an existing file, in three places only: the startup sweep (vault roots only), a note append (`NoteWriter`, under the note's lock), and session rename recovery. Atomic writes never consume it, so read-modify-write state files such as `session.json` and the external-note registry are untouched; their copies are kept for manual recovery only. Installing a previously missing target renames any restorable copies of that name to the plain name. Only the newest copy is tried: if its move fails, nothing is restored and all copies stay; links, placeholders and non-files are skipped. With several copies the newest is restored and older ones are renamed to the plain name, not deleted. The target name is validated (plain file name, not dot-prefixed, no separators, valid vault component) before any move; names over 100 UTF-8 bytes and case-only mismatches are not auto-restored (per-note locks are case-sensitive, so a case-mismatched race can leave the copy hidden, without overwriting anything). The event is also written to the app log), and any path component that is a reparse point (symlink or junction) is refused where the Mac refuses symlinks. The app manifest declares long-path awareness, so paths beyond 260 characters work. ([windows/src/CaptureApp.Core/NoteFile.cs](windows/src/CaptureApp.Core/NoteFile.cs), [windows/src/CaptureApp.Core/SectionedJsonFile.cs](windows/src/CaptureApp.Core/SectionedJsonFile.cs), [windows/src/CaptureApp.App/app.manifest](windows/src/CaptureApp.App/app.manifest))

`VaultNamingRules` keeps the Mac rules (32 components, 900 bytes, `..`, `~$`, reserved `assets`) and, on Windows, also accepts `\` as a separator and rejects the reserved device names `CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9` and `LPT1`-`LPT9` (including the superscript digits, with or without an extension), the characters `<>:"|?*` and control characters, and trailing spaces or periods. A leading `/` resolves from `%USERPROFILE%`, and external-note paths stay `/`-separated and home-relative so the registry file is portable. The Mac accepts some of these names, which is a registered deviation (DV7). ([windows/src/CaptureApp.Core/NoteTitle.cs](windows/src/CaptureApp.Core/NoteTitle.cs), [windows/src/CaptureApp.Core/Router.cs](windows/src/CaptureApp.Core/Router.cs), [windows/tests/CaptureApp.Core.Tests/VaultNamingWindowsTests.cs](windows/tests/CaptureApp.Core.Tests/VaultNamingWindowsTests.cs))

### Updates and release packaging

Installs and updates use Velopack. `windows/scripts/pack.ps1` publishes the app self-contained for one runtime and runs `vpk pack` with that architecture's pack id (`<app name>-win-x64` or `<app name>-win-arm64`), runtime and channel, so the two architectures' assets never collide in one GitHub release; it fails on assets without the runtime in their name and on duplicates across architectures. It signs with the `WINDOWS_SIGN_TEMPLATE` when that is set, and otherwise produces unsigned Authenticode binaries. `vpk` is pinned as a local dotnet tool at the same version as the Velopack package. ([windows/scripts/pack.ps1](windows/scripts/pack.ps1), [windows/.config/dotnet-tools.json](windows/.config/dotnet-tools.json))

Velopack checks package hashes but not who published them, so the release job also signs each `releases.win-<arch>.json` with an Ed25519 key. The `.sig` file is `{format, keyId, channel, signature}`; the signature covers a fixed domain-separation line, the channel and the exact index bytes, so an index cannot be replayed on another channel. The app pins a set of public keys (`<keyId>:<base64>`, comma separated) from `WINDOWS_UPDATE_ED_KEYS` in `Config/app.env`, verifies the signature before any download, and treats a missing, malformed, wrongly keyed, wrong-channel or invalid signature as a failed check. The set holds an active key K1 and an offline standby K2, so a release can rotate without stranding installed copies; an empty set disables updates. This is separate from the Mac Sparkle key. Stable checks resolve the `releases/latest` redirect on GitHub to a concrete tag (no API rate limit) and read the index and packages from that release; an optional prerelease setting looks up the newest non-draft release instead. Automatic checks run every 24 hours and back off 1, 4, 12, then 24 hours after failures, honoring `Retry-After`; a manual check bypasses the backoff. Automatic checks start only once the update choice is answered with automatically, through one schedule per launch; an unanswered choice runs none. If applying a downloaded update throws at quit, the app logs it and still exits, and the next launch counts the pending apply as a failed attempt. ([windows/src/CaptureApp.Updates/IndexSignature.cs](windows/src/CaptureApp.Updates/IndexSignature.cs), [windows/src/CaptureApp.Updates/TrustedKeys.cs](windows/src/CaptureApp.Updates/TrustedKeys.cs), [windows/src/CaptureApp.Updates/VerifiedUpdateSource.cs](windows/src/CaptureApp.Updates/VerifiedUpdateSource.cs), [windows/src/CaptureApp.Updates/IndexFetcher.cs](windows/src/CaptureApp.Updates/IndexFetcher.cs), [windows/src/CaptureApp.Updates/UpdateBackoff.cs](windows/src/CaptureApp.Updates/UpdateBackoff.cs), [windows/tools/IndexSigner](windows/tools/IndexSigner), [scripts/make-windows-update-key.sh](scripts/make-windows-update-key.sh))

`windows/scripts/signing-inventory.ps1` lists every PE file in the installed layout and in each shipped installer artifact and classifies it as ours and signed by a pinned certificate thumbprint (`WINDOWS_SIGNER_THUMBPRINTS`), vendor-signed, or an unmodified upstream binary on a hash allow-list. Release runs enforce this inventory only when all Authenticode inputs are configured; with no signer configuration it records unsigned files and does not reject the package. Partial signing configuration fails the release gate. ([windows/scripts/signing-inventory.ps1](windows/scripts/signing-inventory.ps1), [windows/scripts/upstream-allowlist.json](windows/scripts/upstream-allowlist.json))

Authenticode signing is optional and does not control Windows release availability. Every release push builds both Windows architectures when the update-signing public keys in `Config/app.env` and the matching K1 private secret are present. The Mac release job signs each Windows update index with K1, verifies it against the committed public keys, adds the Windows assets to `SHA256SUMS.txt`, attests them, and uploads them to the same draft release. The app verifies the Ed25519 index signature and package hashes before updating, whether or not the installer has an Authenticode signature. ([.github/workflows/release.yml](.github/workflows/release.yml), [scripts/windows-release-gate.sh](scripts/windows-release-gate.sh))

### Continuous integration

The `checks.yml` workflow runs builds and tests on demand. The `run-ci` PR label selects lean checks only for changed platforms: a macOS build/core check and/or a Windows x64 build/functional test run. Documentation-only changes skip native runner jobs. The `run-ci-full` label or the manual workflow's Full checks option selects the complete architecture, model, performance, gallery, bundle, installer and update matrix, including the macOS 15 smoke test. A manual lean run checks both platforms. Use the full profile before releases and for changes to packaging, model inference, native runtimes or architecture-specific behavior. PR labels create PR check records; a manual branch dispatch is a separate workflow run. After pushing another commit, remove and re-add the run label for fresh validation; keeping it attached does not trigger builds on pushes. A newer requested run cancels older checks for the same PR.

The `skip-ci` PR label takes precedence over both run labels. The selector and native checks are skipped, while two short Ubuntu gate jobs report success under the required `build` and `smoke-macos-15` check names. These jobs must execute because GitHub can leave dynamic names unevaluated on skipped jobs. Explicit lean requests also execute a lightweight gate when the corresponding native checks are omitted. Open/reopen and new-commit events renew the successful gates while the skip label remains attached. Other unrelated events do not execute these gates or publish canonical required names, so they cannot accidentally satisfy the CI requirement. Removing `skip-ci` posts a failing `build` check from a short Ubuntu job, revoking the earlier bypass when that check completes. Selector failures and cancellations also fail the build gate; the smoke gate fails when its prerequisite build fails or is cancelled. Adding the skip label cancels requested work already in progress; it cannot undo work that has already run. Label events use webhook snapshots, and check updates and cancellations are asynchronous. Review/approval rules, local hooks, and release verification remain independent. ([CONTRIBUTING.md](CONTRIBUTING.md#choosing-ci-checks), [.github/workflows/checks.yml](.github/workflows/checks.yml))

Pre-commit checks staged whitespace. Pre-push selects host-relevant source changes across the complete pushed range, checks the exact clean checkout, and runs the host build, functional checks and performance gates once. Documentation-only, other-platform, tag and deletion pushes skip native checks; existing custom hooks are preserved during installation with `bash scripts/install-hooks.sh`. Lean CI excludes benchmark workloads (`CoreChecks --skip-performance`, or the .NET `Category!=Perf` filter). Full CI and release validation set `FOCUSNOTES_PERF_GATES=0` to keep timing measurements diagnostic; local speed assertions use `FOCUSNOTES_PERF_GATES=1`. Large-vault indexing/search, OCR and clipboard workloads verify their results when selected; deadline and cancellation checks remain functional tests without tight elapsed upper limits. Product deadlines remain part of runtime behavior, and generous test/step timeouts catch hangs. | `release.yml` / `windows-gate`, `windows` | Windows assets are built for every release push when K1 update signing is configured. Authenticode signing is optional; it is enforced only when all three signing inputs are set, while partial configuration fails. Without those inputs the Windows matrix records a report-only inventory and still uploads unsigned assets. The Mac `release` job signs the indexes with `WINDOWS_UPDATE_ED_KEY_1`, adds Windows files to `SHA256SUMS.txt`, attests the DMG and Windows binaries, then uploads everything to the same draft release. ([.github/workflows/release.yml](.github/workflows/release.yml), [scripts/windows-release-gate.sh](scripts/windows-release-gate.sh)) |
