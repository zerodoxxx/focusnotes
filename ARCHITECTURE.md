## Runtime and package boundaries

This document describes both native FocusNotes editions. The package boundaries below cover macOS; the implemented
Windows edition under `windows/` is covered in [Windows edition](#windows-edition). Windows installers are not part
of the currently published releases.

## App startup and ownership

On normal launch, `ApplicationDelegate` reads `vaultPath` from `UserDefaults` or selects `Documents/<app name>`, and places app state under `Library/Application Support/<bundle identifier>`. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L21-L33), [Sources/App/AppInfo.swift](Sources/App/AppInfo.swift#L3-L14))

`CapturePipeline.open` prepares the vault and constructs the session store, note writer and capture service, keyword index, semantic indexer, vault monitor, capture journal, draft store, and pin store. The keyword database is `index.sqlite`; the semantic indexer owns a separate `vectors.sqlite` database, and the models directory defaults to `<state>/models` unless an override is passed. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L46-L72), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L35-L50))

`AppController` is main-actor isolated and coordinates UI commands, while `CapturePipeline` exposes the storage and indexing services used by those commands. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L115-L126), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L33-L44))

Startup replays unsaved journal records before loading the current session; for interactive launches it then registers shortcuts, installs the menu bar item, and may show the Accessibility guide, before starting vault observation, index synchronization, and OCR backfill. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L183-L215))

Termination stops the watcher and semantic work, unregisters hotkeys, and drains acquisition and save work for five seconds by default; it waits for recovery-journal writes and logs failures, while timeout logs that prepared captures remain in the journal. Actual retention depends on those journal writes succeeding. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L447-L515), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L27-L35))

## Capture and save path

Carbon global hotkeys invoke selection capture, area capture, search, session toggle, note editor, subheading entry, and vault-folder opening; registration failures are retained and surfaced while menu commands remain available. ([Sources/CaptureKit/Hotkeys.swift](Sources/CaptureKit/Hotkeys.swift#L49-L63), [Sources/CaptureKit/Hotkeys.swift](Sources/CaptureKit/Hotkeys.swift#L89-L121), [Sources/App/AppController.swift](Sources/App/AppController.swift#L218-L244), [Sources/App/AppController.swift](Sources/App/AppController.swift#L1020-L1069))

Capture context is snapshotted at hotkey entry; selection capture first reads the focused element's Accessibility selection, then may use a Command-C clipboard fallback that snapshots and conditionally restores pasteboard contents. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L260-L274), [Sources/CaptureKit/FrontmostContext.swift](Sources/CaptureKit/FrontmostContext.swift#L17-L41), [Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L71-L84), [Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L87-L129))

The selection path checks secure-input state, Accessibility trust, and whether the captured app remains frontmost; area capture checks Screen Recording permission and invokes `/usr/sbin/screencapture` to write a PNG in a temporary directory. ([Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L72-L80), [Sources/CaptureKit/SelectionReader.swift](Sources/CaptureKit/SelectionReader.swift#L97-L129), [Sources/CaptureKit/RegionCapturer.swift](Sources/CaptureKit/RegionCapturer.swift#L25-L34), [Sources/CaptureKit/RegionCapturer.swift](Sources/CaptureKit/RegionCapturer.swift#L43-L75))

Vision OCR classifies a region as text or image from OCR coverage, confidence, and line count; if OCR takes more than 1.5 seconds, the pending capture retains the PNG and holds OCR for deferred completion. ([Sources/CaptureKit/CaptureClassifier.swift](Sources/CaptureKit/CaptureClassifier.swift#L19-L48), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L226-L258))

`Capture` represents text, image, subheading, and typed-note content with a UUID, timestamp, and optional source app/window metadata. Ordinary captures with a non-empty note title match root-note titles first, session titles second, then Inbox; an unmatched title creates a new root note. Without a note title, routing selects the active session or Inbox. Standalone typed notes retain an explicit Browse destination or append to the active session. Otherwise, `TypedNote` extracts the first-line name: valid unprefixed slash-separated names resolve beneath the vault, and a leading slash after title cleaning resolves beneath HOME. Relative malformed slash forms such as URLs, trailing or repeated separators, and whitespace adjacent to a separator use the legacy flat filename cleanup; explicit HOME, traversal, length, depth, reserved `assets/`, and `~$` leaf errors remain errors. Existing folder and filename casing is reused case-insensitively. A typed note's name resolves to exactly one path (`archive/foo` is `archive/foo.md`, `foo` is the vault-root `foo.md`); there is no matching by title or across folders. `CaptureService.appendTarget` is the shared, non-mutating rule that both `prepareNote` and the quick-note “Add to note”/Save as New Note hint use: a bare name matching Inbox appends to `Inbox.md`; otherwise a resolved path that exists on disk, or was reserved by an earlier unsaved typed note in the same process (compared case-insensitively), is appended to. Otherwise the path is created. A title-only note appends its own text. A forced new note (Save as New Note) or a generated timestamp title always creates a note, taking a numbered ` 2`, ` 3`, … suffix in the same folder when the path exists or is reserved. New parent folders are created during the managed write. Starting a session is unchanged: it resumes a flat session note by exact file name or legacy dated file name, and qualified session names are rooted under `Sessions/`. ([Sources/Core/Capture.swift](Sources/Core/Capture.swift), [Sources/Core/Router.swift](Sources/Core/Router.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift), [Sources/Core/TypedNote.swift](Sources/Core/TypedNote.swift), [Sources/Core/NoteTitle.swift](Sources/Core/NoteTitle.swift), [Sources/Core/SessionStore.swift](Sources/Core/SessionStore.swift), [Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift), [Sources/App/AppController.swift](Sources/App/AppController.swift))

The pipeline prepares a fixed destination before saving, stores a job in the recovery journal before waiting on earlier commits, then writes via `CaptureService` and `NoteWriter`; image jobs carry a stable vault-relative asset path. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L75-L94), [Sources/App/AppController.swift](Sources/App/AppController.swift#L393-L423))

Journal records are JSON plus an optional PNG under the app state's `unsaved/` folder; replay preserves the prepared destination, uses an available OCR transcript if a journaled PNG is missing, and quarantines records that fail record decoding or identity validation. ([Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L13-L35), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L41-L92), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L141-L163))

Text and image capture markers include an identity and timestamp, typed-note markers include an identity and timestamp, and subheading markers include an identity without a timestamp. Image jobs use a vault-relative `assets/` path that Markdown renders as a link; `NoteWriter` computes a relative prefix from the note's directory back to the selected vault, so nested and external notes still link to that vault's assets. `NoteParser` accepts indexed image links only when their resolved target is inside the vault's `assets/`. On retry, `appendIfMissing` passes a stable marker and `NoteFile` checks existing block content or the typed-note marker before suppressing a second append. ([Sources/Core/CaptureFormat.swift](Sources/Core/CaptureFormat.swift#L21-L41), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift#L53-L78), [Sources/Core/NoteWriter.swift](Sources/Core/NoteWriter.swift#L81-L95), [Sources/Core/CaptureFormat.swift](Sources/Core/CaptureFormat.swift#L163-L189), [Sources/Core/Index/NoteParser.swift](Sources/Core/Index/NoteParser.swift#L227-L270), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L400-L416), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L562-L570))

A failed per-capture reindex is logged without retrying the Markdown append; startup starts the watcher and runs `index.sync()` over vault notes, while sync failures are logged separately. The journal record is removed after note-save and draft/pin completion. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L96-L123), [Sources/App/AppController.swift](Sources/App/AppController.swift#L205-L211), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L168-L176), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L63-L108))

## Vault files and app state

The vault contains `Inbox.md`, Markdown notes at any depth, the `Sessions/` namespace, and the reserved `assets/` directory. `Vault.prepare` creates the managed directories and Inbox when they are missing; note discovery recurses through visible folders and excludes the root entry named `assets` case-insensitively, keeping case-variant asset folders out of the note index as well. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift#L187-L208), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L220-L228), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L231-L256), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L624-L664))

Standalone typed-note paths can target the vault or HOME. `external-notes.json` in app state records exact HOME-relative note paths before append so journal replay can reuse them; it stores no note contents and does not cause a HOME scan. The registry caches a validated path snapshot and generation, invalidated when its file or parent changes. Vault note IDs are vault-relative paths, while external note IDs are canonical file URLs. Listing and indexing include only registered external paths. Capture preparation validates and reuses one registry snapshot before scanning notes; registry errors remain visible instead of routing against an incomplete list. If the vault volume is unavailable, deterministic fallback routing is allowed only when the valid registry has no external registrations. A malformed, unsupported, or unsafe registry is preserved; external paths fail closed, a warning explains the condition, and registry-dependent listing, indexing, and capture routing pause until recovery. Local Markdown remains intact, and managed vault-file operations remain available. A valid registry recovery rebuilds external indexing and watching. ([Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift), [Sources/Core/ExternalNoteRegistry.swift](Sources/Core/ExternalNoteRegistry.swift), [Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/CaptureService.swift](Sources/Core/CaptureService.swift))

Markdown notes and image assets are the persistent content; SQLite indexes and app-state JSON are separate derived or workflow state. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L45-L46), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L46-L72), [Sources/App/CaptureJournal.swift](Sources/App/CaptureJournal.swift#L21-L35), [Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L35-L43), [Sources/App/NotePinStore.swift](Sources/App/NotePinStore.swift#L3-L8))

An active session points to a note path under `Sessions/`, while its current name, path, and start date are persisted as `session.json` in app state; pinned-note paths are stored in `pinned-notes.json`, separately from Markdown. A bare name resumes one matching session at its full path, opens a newest-first title/path/date picker for duplicate matches, or creates a top-level session when there is no match. The picker also offers rename-and-resume with Cmd+Enter on macOS and Ctrl+Enter on Windows. Rename uses a same-directory temporary file and atomic replacement for the title heading, preserves managed-file identity and path checks, and exclusively publishes the new filename without overwriting a destination. The app migrates pins and pending capture destinations to the new ID and synchronizes the search index. A valid slash-qualified name resolves directly under `Sessions/`; relative malformed slash forms such as `pros / cons`, `TODO/`, or `a//b` fall back to the cleaned flat-name matching flow. A leading slash after title cleaning is an explicit HOME-relative target for typed notes and remains invalid for sessions; names containing NUL also remain errors. ([Sources/Core/SessionStore.swift](Sources/Core/SessionStore.swift), [Sources/App/AppController.swift](Sources/App/AppController.swift), [Sources/OverlayKit/InputPanel.swift](Sources/OverlayKit/InputPanel.swift), [Sources/App/NotePinStore.swift](Sources/App/NotePinStore.swift#L3-L8))

On Windows, `session-rename.json` durably records the source and staged-file identities, target, content hashes, and affected capture UUIDs before a rename changes the file. If the file moves but session or pin migration fails, the pipeline returns a pending outcome, keeps the intent, and retries recovery at startup and before further saves. A known moved or installed inode is adopted even after user edits; only an untouched original heading is rewritten. If the source remains at its old path, or the target is missing or unrelated, recovery logs and abandons the stale intent while preserving note bytes, so it cannot repeatedly block startup or captures. Cleanup deletes only staging files with the recorded identity. Search updates are best effort because the index is a cache. ([windows/src/CaptureApp.AppCore/CapturePipeline.cs](windows/src/CaptureApp.AppCore/CapturePipeline.cs), [windows/src/CaptureApp.Core/SessionStore.cs](windows/src/CaptureApp.Core/SessionStore.cs), [windows/src/CaptureApp.Core/NoteFile.Rename.cs](windows/src/CaptureApp.Core/NoteFile.Rename.cs))

The note editor draft and pin-on-save intent are stored together in `draft-note.json` using atomic replacement, with a legacy `draft-note.md` read path; note pins are separately serialized as an atomic JSON list. If a saved note's identity cannot be resolved for pinning, the note save succeeds and a warning makes the pin failure visible. ([Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L4-L7), [Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L35-L43), [Sources/App/NoteDraftStore.swift](Sources/App/NoteDraftStore.swift#L206-L239), [Sources/App/NotePinStore.swift](Sources/App/NotePinStore.swift#L34-L43), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift))

Vault and external HOME reads and writes use their selected root's retained directory descriptor and `openat` with `O_NOFOLLOW`; managed regular files must be owned by the current user and have one hard link. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift#L194-L208), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L390-L405), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L124-L176), [Sources/Core/NoteFile.swift](Sources/Core/NoteFile.swift#L207-L225))

## Keyword index and change monitoring

`SearchIndex` is a disposable SQLite cache: it checks FTS5 availability, validates an existing schema/version and SQLite integrity, and discards an invalid cache before creating a fresh one. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L45-L61), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L419-L449))

Its schema stores note metadata, parsed blocks, and image OCR text, then indexes note title, block body, and OCR text in an FTS5 table; the indexing code maps each parsed block and its OCR text into those fields. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L309-L343), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L451-L469))

`NoteParser` reads the Markdown title and recognized capture markers, and also retains ordinary Markdown regions as loose blocks for indexing. ([Sources/Core/Index/NoteParser.swift](Sources/Core/Index/NoteParser.swift#L22-L69), [Sources/Core/Index/NoteParser.swift](Sources/Core/Index/NoteParser.swift#L245-L268))

Index synchronization recursively scans visible Markdown below the vault root, excluding the root `assets` entry case-insensitively, and adds only exact external paths from the registry. It validates each file through its vault or HOME descriptor anchor, compares modification-time/size fingerprints, reparses changed files, and deletes cached rows for notes no longer present. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift#L231-L256), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L524-L533), [Sources/Core/Vault.swift](Sources/Core/Vault.swift#L624-L664), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L63-L108))

Keyword search sanitizes query tokens before passing them to FTS5 and returns ranked hits with snippets; an empty search uses the recent-capture query. ([Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L174-L216), [Sources/Core/Index/SearchIndex.swift](Sources/Core/Index/SearchIndex.swift#L381-L399))

`VaultWatcher` keeps recursive FSEvents on the vault root. Registered HOME notes use bounded `O_EVTONLY` vnode sources: at most 128 descriptors are retained in total, including registry file/parent sources, with no more than 64 registered-note parent-directory watches. A nonrecursive vnode may watch HOME when it is the nearest existing parent needed to re-arm a missing path. Paths without vnode coverage are fingerprint-polled every 15 seconds by checking exact registered paths only; HOME is never scanned. External vnode setup, snapshot, and registry failures request a full sync for each newly reported failure key; repeats of the same key are logged once until recovery clears it, while a distinct key still requests its own sync. If the vault FSEvents stream cannot start, the watcher reports the failure and requests a full sync, then remains stopped until an explicit start retry succeeds. Uncovered external paths retry watcher setup after descriptors close and on a timer, while healthy polling does not trigger periodic syncs. Parent events recheck only registered paths in that directory, suppress unrelated HOME churn, and rearm sources after file or parent replacement. The registry file and its parent are watched as control state; malformed, unsupported, or unreadable states clear external watches and request a full sync, and a valid recovery rebuilds them. Vault changes to nested Markdown and the top-level `assets` directory are reported in their respective note or asset paths, while FSEvents loss/root-change flags and relevant directory renames or removals request a full sync. ([Sources/Core/Vault.swift](Sources/Core/Vault.swift), [Sources/Core/VaultWatcher.swift](Sources/Core/VaultWatcher.swift), [Sources/App/VaultMonitor.swift](Sources/App/VaultMonitor.swift))

`VaultMonitor` coalesces changes into utility-priority index/OCR work without idle polling, and capture-pipeline backfill runs Vision OCR for image assets missing cached text. ([Sources/App/VaultMonitor.swift](Sources/App/VaultMonitor.swift#L12-L24), [Sources/App/VaultMonitor.swift](Sources/App/VaultMonitor.swift#L65-L109), [Sources/App/CapturePipeline.swift](Sources/App/CapturePipeline.swift#L181-L199))

## Optional semantic search

In normal app operation, semantic search is enabled when every `ModelManifest.requiredFiles` path exists and is not a directory; this list consists of manifest model-file paths plus the ONNX Runtime library name. The manifest pins an EmbeddingGemma revision and ONNX Runtime archive and records SHA-256 digests for model and runtime artifacts. ([Sources/EmbedKit/ModelManifest.swift](Sources/EmbedKit/ModelManifest.swift#L71-L75), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L49-L56), [Sources/EmbedKit/ModelManifest.swift](Sources/EmbedKit/ModelManifest.swift#L77-L114))

The menu asks before downloading or removing models; downloads use HTTPS, resume partial files, verify pinned hashes, and stage the completed installation before committing it. ([Sources/App/SemanticModelsMenu.swift](Sources/App/SemanticModelsMenu.swift#L73-L85), [Sources/App/SemanticModelsMenu.swift](Sources/App/SemanticModelsMenu.swift#L131-L146), [Sources/ModelInstall/ModelTransport.swift](Sources/ModelInstall/ModelTransport.swift#L16-L55), [Sources/ModelInstall/ModelInstaller.swift](Sources/ModelInstall/ModelInstaller.swift#L249-L289), [Sources/ModelInstall/ModelInstaller.swift](Sources/ModelInstall/ModelInstaller.swift#L220-L243))

`SemanticIndexer` reconciles disposable vectors against indexed note blocks and stores them separately in `vectors.sqlite`; text and OCR embeddings use content fingerprints, while image embeddings use asset path, size, and modification time. ([Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L35-L50), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L190-L253), [Sources/EmbedKit/EmbeddingFingerprint.swift](Sources/EmbedKit/EmbeddingFingerprint.swift#L4-L25))

The app launches `EmbedHelper` as a child process and exchanges one JSON request/response per line through standard pipes; the helper loads the local ONNX models, and `ONNXRuntime` verifies the runtime library digest before `dlopen`. ([Sources/EmbedKit/EmbedClient.swift](Sources/EmbedKit/EmbedClient.swift#L5-L22), [Sources/EmbedKit/EmbedClient.swift](Sources/EmbedKit/EmbedClient.swift#L208-L230), [Sources/EmbedKit/EmbedProtocol.swift](Sources/EmbedKit/EmbedProtocol.swift#L3-L33), [Sources/EmbedHelper/main.swift](Sources/EmbedHelper/main.swift#L41-L79), [Sources/EmbedKit/ONNXRuntime.swift](Sources/EmbedKit/ONNXRuntime.swift#L12-L29))

For a non-empty search query, the app requests keyword and semantic results concurrently and combines their rankings; the semantic branch returns an empty result after its 350 ms deadline, and image embedding work runs only when thermal state is nominal or fair, Low Power Mode is off, and AC power is reported or unavailable. ([Sources/App/AppController.swift](Sources/App/AppController.swift#L894-L905), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L280-L315), [Sources/EmbedKit/SemanticDeadline.swift](Sources/EmbedKit/SemanticDeadline.swift#L3-L25), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L266-L272), [Sources/App/SemanticIndexer.swift](Sources/App/SemanticIndexer.swift#L317-L332))

`SearchPanelController` awaits the query provider and applies returned sections only if that query remains current; existing rows can remain visible while the provider runs. ([Sources/OverlayKit/SearchPanel.swift](Sources/OverlayKit/SearchPanel.swift#L272-L307))

## Windows edition

The Windows edition is a separate, implemented C# codebase under `windows/` (.NET 10 with WPF) that reuses the Mac app's behaviour, not its code. It supports Windows 10 22H2 and Windows 11 on x64 and arm64; Windows installers are not part of the currently published releases. The Mac sections above are unchanged by it. The solution builds with warnings as errors, nullable references, and locked NuGet restore; `Directory.Build.props` reads the app name, bundle prefix, version, repository and Windows update keys from `Config/app.env`, so those still live only there. ([windows/CaptureApp.sln](windows/CaptureApp.sln), [windows/Directory.Build.props](windows/Directory.Build.props), [windows/Directory.Packages.props](windows/Directory.Packages.props), [windows/global.json](windows/global.json), [Config/app.env](Config/app.env))

### Conformance suite

Vault behaviour is kept identical across platforms by language-neutral fixtures in `conformance/scenarios/<area>/<id>.json` (areas: `captureformat`, `noteparser`, `notetitle`, `notewriter`, `router`, `searchindex`, `sessionstore`, `vault-naming`). A case seeds a vault from `input.files`, runs `input.ops` with a fixed clock and time zone, and records `expected.files` (the full final tree) and one `expected.results` entry per operation, with known Core errors as `{ "error": kind }`. Swift is the reference: `swift run CoreChecks --write-conformance` regenerates every `expected` block, plain `swift run CoreChecks` replays them, and `expected` values are never edited by hand. The C# side loads the same files and executes each area through `AreaExecutors`, so a case passes only when both implementations produce the same bytes and results. OCR fixtures live separately in `conformance/ocr/`; the 10 en-US records retained for Windows are filtered from an earlier Mac Vision run, not a newly run Vision baseline. ([conformance/README.md](conformance/README.md), [Sources/CoreChecks/ConformanceChecks.swift](Sources/CoreChecks/ConformanceChecks.swift), [Sources/CoreChecks/main.swift](Sources/CoreChecks/main.swift), [windows/tests/CaptureApp.Conformance.Tests/AreaExecutors.cs](windows/tests/CaptureApp.Conformance.Tests/AreaExecutors.cs), [windows/tests/CaptureApp.Conformance.Tests/ConformanceTests.cs](windows/tests/CaptureApp.Conformance.Tests/ConformanceTests.cs))

### File layer, paths and naming

`NoteFile` replaces the Darwin `flock`/`open` layer: files are opened with exclusive sharing, appends are flushed to disk, atomic writes go through a temporary file and `File.Replace`, and any path component that is a reparse point (symlink or junction) is refused where the Mac refuses symlinks. The app manifest declares long-path awareness, so paths beyond 260 characters work. ([windows/src/CaptureApp.Core/NoteFile.cs](windows/src/CaptureApp.Core/NoteFile.cs), [windows/src/CaptureApp.Core/SectionedJsonFile.cs](windows/src/CaptureApp.Core/SectionedJsonFile.cs), [windows/src/CaptureApp.App/app.manifest](windows/src/CaptureApp.App/app.manifest))

`VaultNamingRules` keeps the Mac rules (32 components, 900 bytes, `..`, `~$`, reserved `assets`) and, on Windows, also accepts `\` as a separator and rejects the reserved device names `CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9` and `LPT1`-`LPT9` (including the superscript digits, with or without an extension), the characters `<>:"|?*` and control characters, and trailing spaces or periods. A leading `/` resolves from `%USERPROFILE%`, and external-note paths stay `/`-separated and home-relative so the registry file is portable. The Mac accepts some of these names, which is a registered deviation (DV7). ([windows/src/CaptureApp.Core/NoteTitle.cs](windows/src/CaptureApp.Core/NoteTitle.cs), [windows/src/CaptureApp.Core/Router.cs](windows/src/CaptureApp.Core/Router.cs), [windows/tests/CaptureApp.Core.Tests/VaultNamingWindowsTests.cs](windows/tests/CaptureApp.Core.Tests/VaultNamingWindowsTests.cs))

### State, watcher and index

State lives in `%LocalAppData%\<bundle id>`, separate from the install directory because Velopack replaces the installed copy on update. It holds the same files as the Mac state directory (`settings.json`, drafts, pins, external notes, `session.json`, `unsaved/` journal, disposable `index.sqlite`, models) plus `logs/`. A locked file there enforces one instance per user, and a named pipe hands a second launch's request to show the app to the first. The default vault is `Documents\focusnotes`. ([windows/src/CaptureApp.AppCore/StatePaths.cs](windows/src/CaptureApp.AppCore/StatePaths.cs), [windows/src/CaptureApp.AppCore/SingleInstance.cs](windows/src/CaptureApp.AppCore/SingleInstance.cs), [windows/src/CaptureApp.AppCore/CaptureJournal.cs](windows/src/CaptureApp.AppCore/CaptureJournal.cs), [windows/src/CaptureApp.Platform/Shell/KnownFolders.cs](windows/src/CaptureApp.Platform/Shell/KnownFolders.cs))

`VaultWatcher` uses one `FileSystemWatcher` (`ReadDirectoryChangesW`) per watched directory with an enlarged buffer; a watcher error or buffer overflow schedules a rescan that enumerates the tree instead of trusting events, a stopped watcher is recreated, and after three errors on one watch it falls back to timed rechecks, so nothing polls while idle and healthy. The index uses the same FTS5 schema as the Mac (`blocks_fts(title, body, ocr)`, `unicode61 remove_diacritics 2`, prefix `2 3`, bm25 weights 5/1/0.8) through `Microsoft.Data.Sqlite` on the bundled SQLite from `SQLitePCLRaw.bundle_e_sqlite3`, and probes FTS5 when it opens. ([windows/src/CaptureApp.Core/VaultWatcher.cs](windows/src/CaptureApp.Core/VaultWatcher.cs), [windows/src/CaptureApp.AppCore/VaultMonitor.cs](windows/src/CaptureApp.AppCore/VaultMonitor.cs), [windows/src/CaptureApp.Core/Index/SearchIndex.cs](windows/src/CaptureApp.Core/Index/SearchIndex.cs), [windows/src/CaptureApp.Core/Index/SQLiteDatabase.cs](windows/src/CaptureApp.Core/Index/SQLiteDatabase.cs))

### Selection capture

`SelectionReader` follows the Mac safety contract guarantee by guarantee: it rejects the app's own windows, runs one capture at a time, re-checks the foreground window before and after each step, and refuses password fields. When UI Automation cannot tell whether the focused field is safe, it re-reads it up to twice, 50 ms apart, then refuses rather than injecting. It reads the selection with UI Automation `TextPattern`; only when that yields nothing and the user enabled the fallback does it send Ctrl+C. Before injecting it waits up to 200 ms for held modifier keys to release (and aborts with "Release the shortcut keys and try again" if they do not), snapshots the clipboard (capped at 64 MB and 250 ms, aborting rather than restoring partially), requires the clipboard sequence number to be unchanged, waits up to 500 ms for the copy, and restores the original formats only while the sequence number still matches. Elevated targets are refused before injection. ([windows/src/CaptureApp.Platform/Selection/SelectionReader.cs](windows/src/CaptureApp.Platform/Selection/SelectionReader.cs), [windows/src/CaptureApp.Platform/Selection/ClipboardSnapshot.cs](windows/src/CaptureApp.Platform/Selection/ClipboardSnapshot.cs), [windows/src/CaptureApp.Platform/Selection/ClipboardGuard.cs](windows/src/CaptureApp.Platform/Selection/ClipboardGuard.cs), [windows/src/CaptureApp.Platform/Selection/ElevationCheck.cs](windows/src/CaptureApp.Platform/Selection/ElevationCheck.cs), [windows/src/CaptureApp.Platform/PlatformStrings.cs](windows/src/CaptureApp.Platform/PlatformStrings.cs))

### Semantic helper

The helper speaks the same newline-delimited JSON protocol as the Mac helper. Because ONNX Runtime already ships for OCR, the opt-in downloads only the EmbeddingGemma model files from the pinned Hugging Face revision (about 455 MB), each checked against a pinned SHA-256. The parent assigns the helper to a Job Object with kill-on-close, so it cannot outlive the app. The helper runs with EcoQoS power throttling, below-normal priority and background I/O mode in place of the Mac's thermal check; image embedding additionally waits for AC power and battery saver off, using the power monitor. ### Updates and release packaging

Installs and updates use Velopack. `windows/scripts/pack.ps1` publishes the app self-contained for one runtime and runs `vpk pack` with that architecture's pack id (`<app name>-win-x64` or `<app name>-win-arm64`), runtime and channel, so the two architectures' assets never collide in one GitHub release; it fails on assets without the runtime in their name and on duplicates across architectures. It signs with the `WINDOWS_SIGN_TEMPLATE` when that is set. `vpk` is pinned as a local dotnet tool at the same version as the Velopack package. ([windows/scripts/pack.ps1](windows/scripts/pack.ps1), [windows/.config/dotnet-tools.json](windows/.config/dotnet-tools.json))

Velopack checks package hashes but not who published them, so the release job also signs each `releases.win-<arch>.json` with an Ed25519 key. The `.sig` file is `{format, keyId, channel, signature}`; the signature covers a fixed domain-separation line, the channel and the exact index bytes, so an index cannot be replayed on another channel. The app pins a set of public keys (`<keyId>:<base64>`, comma separated) from `WINDOWS_UPDATE_ED_KEYS` in `Config/app.env`, verifies the signature before any download, and treats a missing, malformed, wrongly keyed, wrong-channel or invalid signature as a failed check. The set holds an active key K1 and an offline standby K2, so a release can rotate without stranding installed copies; an empty set disables updates. This is separate from the Mac Sparkle key. Stable checks resolve the `releases/latest` redirect on GitHub to a concrete tag (no API rate limit) and read the index and packages from that release; an optional prerelease setting looks up the newest non-draft release instead. Automatic checks run every 24 hours and back off 1, 4, 12, then 24 hours after failures, honoring `Retry-After`; a manual check bypasses the backoff. ([windows/src/CaptureApp.Updates/IndexSignature.cs](windows/src/CaptureApp.Updates/IndexSignature.cs), [windows/src/CaptureApp.Updates/TrustedKeys.cs](windows/src/CaptureApp.Updates/TrustedKeys.cs), [windows/src/CaptureApp.Updates/VerifiedUpdateSource.cs](windows/src/CaptureApp.Updates/VerifiedUpdateSource.cs), [windows/src/CaptureApp.Updates/IndexFetcher.cs](windows/src/CaptureApp.Updates/IndexFetcher.cs), [windows/src/CaptureApp.Updates/UpdateBackoff.cs](windows/src/CaptureApp.Updates/UpdateBackoff.cs), [windows/tools/IndexSigner](windows/tools/IndexSigner), [scripts/make-windows-update-key.sh](scripts/make-windows-update-key.sh))

`windows/scripts/signing-inventory.ps1` lists every PE file in the installed layout and in each shipped installer artifact and classifies it as ours and signed by a pinned certificate thumbprint (`WINDOWS_SIGNER_THUMBPRINTS`), vendor-signed, or an unmodified upstream binary on a hash allow-list; with `-Enforce` anything else fails the run. ([windows/scripts/signing-inventory.ps1](windows/scripts/signing-inventory.ps1), [windows/scripts/upstream-allowlist.json](windows/scripts/upstream-allowlist.json))

### Continuous integration

The `checks.yml` workflow runs on demand: use Actions → checks → Run workflow or `gh workflow run checks.yml --ref <branch>` to check any branch. To run required CI for a pull request, add the `run-ci` label (for example, `gh pr edit 123 --add-label run-ci`); dispatching against a PR branch does not satisfy the branch ruleset's required `build` and `smoke-macos-15` checks. After pushing a new commit, remove and re-add `run-ci` to start a fresh run; keeping the label on the PR does not run CI on pushes. Other label changes do not start the CI jobs.

On both platforms, elapsed benchmark timings are diagnostic in CI because shared runner speed varies; both CI workflows explicitly set `FOCUSNOTES_PERF_GATES=0`. The versioned local pre-push hook invokes native-platform benchmark speed assertions with `FOCUSNOTES_PERF_GATES=1`; install it with `scripts/install-hooks.sh` (existing custom hooks are preserved). Large-vault indexing/search, OCR and clipboard workloads always verify their results; deadline and cancellation checks verify fallback and cleanup without tight elapsed upper limits. Product deadlines remain part of runtime behavior, and generous test/step timeouts catch hangs. ([CONTRIBUTING.md](CONTRIBUTING.md#build-and-checks), [.githooks/pre-push](.githooks/pre-push), [scripts/check-performance.sh](scripts/check-performance.sh))
